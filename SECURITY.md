# Security reports

Report vulnerabilities privately using the repository's GitHub **Security > Report
a vulnerability** facility when available. The maintainer must enable private
vulnerability reporting before public release. If that facility is unavailable,
open an issue asking for a private reporting channel without exploit details,
credentials, personal information or private games; wait for that channel before
sharing sensitive material. No dedicated email address is currently established.

Include the application version, Windows version, reproduction steps, impact and
relevant sanitised logs. Never upload signing keys or tokens.

There is no guaranteed response time, security support period or update schedule.
Fixes and review are at the maintainer's discretion. Purchasing an installer does
not provide a support contract. See [maintenance policy](docs/MAINTENANCE.md).
