# Publish the prepared 1.6.8 release

Published on 2026-10-15 as [OTBMaster3D 1.6.8](https://github.com/nork79/OTBMaster3D/releases/tag/v1.6.8).
The installer and seven companion assets passed public-download SHA-256 checks.
The matching dependency archive is reused from 1.6.5 as described below.

The following records the publication procedure. The original preparation task
created no commit, tag, push or release; publication subsequently completed it.
Run commands from the repository root only when preparing a new publication.

## Review and commit

Review `git diff` and `git status --short`, including the new tests and release
documents. Commit the intended project changes with a message such as
`Release 1.6.8: board rendering, captured material and installer fixes`.
Keep `dist/`, `installer-output/`, `.tmp/` and `release-materials/` out of Git;
the release assets are uploaded separately.

The existing installer was built from an uncommitted workspace on base commit
`c62a117ec14f61b2c4f9a41b5171fa90e382c115`. Its embedded source is preserved.
The new commit also contains release documentation, so its automatic GitHub
source archive is not a substitute for the prepared application-source ZIP.

After committing, create the release tag and push your branch and tag:

```powershell
git tag -a v1.6.8 -m "OTBMaster3D 1.6.8"
git push
git push origin v1.6.8
```

## Upload release assets

Create a GitHub Release for `v1.6.8`, titled `OTBMaster3D 1.6.8`. Use
`docs/releases/1.6.8-source.md` for the description and attach every file listed
in `release-materials/1.6.8/SHA256SUMS.txt` from that same local directory.
This includes the installer, application source ZIP, metadata, validation results
and README. Reuse the dependency source ZIP linked from release 1.6.5; all 75
dependency and Rodent source/build files were verified identical. Do not upload
a duplicate dependency archive. Its URL and SHA-256 are in the pairing manifest. Also upload `SHA256SUMS.txt` itself. Do not upload `.tmp` test logs.

Before uploading, verify the prepared files:

```powershell
Get-Content .\release-materials\1.6.8\SHA256SUMS.txt | ForEach-Object {
    $expected, $name = $_ -split '  ', 2
    $actual = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path '.\release-materials\1.6.8' $name)).Hash
    if ($actual -ne $expected) { throw "Checksum mismatch: $name" }
}
```

Publish all assets together. Verify the public download URLs and downloaded
hashes, then update README.md and SOURCE_ACCESS.md to make 1.6.8 the current
download. Remove the pending-publication wording in the release notes only once
publication succeeds. Do not mark clean Windows installation/upgrade/uninstall
as tested unless those checks are actually completed.

The pairing manifest intentionally records local-only status. If you update its
publication fields after verifying public downloads, regenerate its entry in
SHA256SUMS.txt and replace both assets together. Keep the original embedded
application ZIP and build-info.json unchanged.

## If you rebuild

Rebuilding 1.6.8 overwrites the original installer and frozen application folder.
The prepared release directory retains a separate installer copy. Do not mix a
new installer with these source archives or checksums. Repeat validation and
source preparation for the new build, and update the release document's hashes.
